# Languages (English and French)

The interface and the server's messages come in English and French. English is
the default; French is one click away. The choice is stored per browser.

This page covers how it works, how to add or change a string, and what is
deliberately left alone.

## What is translated

| Translated | Left as it is |
| --- | --- |
| Every page, dialog, tooltip, toast and the command palette | Generated Excel and PDF invoices (they stay French) |
| Dates, months, numbers and money (`en-CA` / `fr-CA`) | The prompts sent to the AI extraction model |
| Error and status messages from the API, including the updater and sync | Server log lines and CLI output |
| Chart labels, month names, plurals | `CLIENT_GUIDE_FR.md`, the French guide for the end user |

The invoices stay French because they go to French-speaking customers and their
template is not part of the interface.

## How the language is chosen

1. The browser reads `localStorage['facturo-lang']` (`en` or `fr`) before the
   first paint. Nothing stored means English.
2. The switcher sets it: the **EN | FR** control in the header, the same control
   in Paramètres / Settings, and the *Language* action in the command palette.
   All three go through one function, so they cannot disagree.
3. Every API call carries an `X-Lang` header with that value. The server answers
   in that language. Without the header it falls back to `Accept-Language`, then
   to English.
4. Changing language re-renders the current page in place. No reload. A dialog
   that is already open keeps the language it was opened in until it closes.

## Browser side

`facturo/web/static/js/i18n.js` exposes `ui.i18n`:

| Call | Does |
| --- | --- |
| `t(key, params)` | The text for `key`. Lookup order: current language, then English, then the key itself. Never throws. |
| `tn(key, count, params)` | Plural form picked with `Intl.PluralRules`. The English key is the base; siblings like `key.one` hold the variants. |
| `fmtMoney`, `fmtNumber`, `fmtDate`, `fmtMonth` | Locale-aware formatting. `fmtDate` parses `YYYY-MM-DD` by hand, because `new Date('2026-09-30')` is UTC midnight and shows the previous day in the Americas. |
| `lang()`, `setLang(code)`, `onLangChange(fn)` | Read, change and observe the language. |
| `define(lang, dict)` | Register a dictionary. Used by the locale files. |

Text lives in `facturo/web/static/js/locales/`, one file per language per area:

```
en.ui.js        fr.ui.js          shell, shared verbs, palette
en.home.js      fr.home.js        Accueil / Home
en.clients.js   fr.clients.js
en.facture.js   fr.facture.js     invoice form, discounts, AI dialog
en.history.js   fr.history.js
en.scans.js     fr.scans.js
en.payments.js  fr.payments.js
en.settings.js  fr.settings.js    includes sync and updates
```

Each file returns a flat `{ 'area.key': 'text' }` object and registers itself
when loaded. Keys are lowercase and dotted (`history.filter.period`). Reuse a
`ui.*` key such as `action.cancel` rather than adding a near-duplicate.
`locales/README.md` has the file shape and naming rules.

### Using a string

In JavaScript that builds HTML, **escape the result**. `t()` returns text, not
markup:

```js
`<h3>${esc(t('clients.empty_title'))}</h3>`
`<input placeholder="${escAttr(t('history.filter.placeholder'))}">`
```

In static markup, use attributes and let the hydrator apply them:

```html
<span data-i18n="nav.home">Accueil</span>
<button data-i18n-attr="aria-label:lang.en,data-tip:lang.en">EN</button>
```

Use `data-tip` for tooltips, not `title`. `ui/tooltip.js` turns every `title`
into a `data-tip`, and the two would overwrite each other.

The static text in `index.html` is French and only matters when JavaScript does
not run. The hydrator replaces it before the first paint, so an English user
does not see it.

## Server side

`facturo/i18n.py` keeps the request's language in a context variable, set by
`I18nMiddleware` (`facturo/i18n_middleware.py`). Code calls `tr()`:

```python
raise HTTPException(404, tr("err.client_not_found"))
raise SyncError(tr("sync.push_failed", detail=_short(e)))
```

Catalogs are in `facturo/i18n_catalog/en/` and `fr/`, one file per area
(`errors`, `clients`, `factures`, `payments`, `scans`, `settings`, `sync`,
`updates`, `ai`, `known_values`). `tr()` falls back to English, then to the key.

Services such as the updater and sync call `tr()` **where they raise**, so the
exception text is already in the request's language and the API just passes it
on. Text produced outside a request, such as the updater's rollback note read at
startup, stores a catalog key and is translated when it is read.

A message must never carry a token or other secret. Several tests check this.

## Adding or changing text

1. Add the key to `en` first. It is the base and the fallback.
2. Add the same key to `fr`, with the same `{placeholders}`.
3. Use it with `t()` (browser) or `tr()` (server).

A missing French key shows English instead of a hole, but tests fail if the two
languages drift, so do both together.

## Adding a third language

1. Add the code to `SUPPORTED` and `LOCALES` in `i18n.js` and to `SUPPORTED` in
   `i18n.py`.
2. Add a locale file per area and a catalog per area, with the same keys as `en`.
3. Add a button to the `data-lang-group` controls (the header and Settings).
4. Run the parity tests below. They fail until every key is present.

## Tests

| Test | Checks |
| --- | --- |
| `tests/js/i18n.test.mjs` | The engine: fallbacks, plurals, formatting, date edge cases, persistence |
| `tests/js/locales-a.test.mjs`, `locales-b.test.mjs` | Same keys and same placeholders in `en` and `fr`, no empty values, no key defined twice |
| `tests/test_i18n.py` | `tr()`, language negotiation, middleware, catalog parity |
| `tests/test_service_i18n.py` | Updater, sync and PDF errors in both languages, end to end through the API |
| `tests/e2e/test_i18n_pages_a.py`, `_b.py` | Every page in English, no raw key on screen, a live switch to French and back |
| `node tests/js/i18n-lint.mjs` | Counts French literals still in the JavaScript. It reports and never fails. |

The e2e `page` fixture starts in French, because most assertions were written
against the French text. `page_en` starts with nothing stored, which is the real
default. The Python `french` fixture in `tests/conftest.py` sets the language for
one test.

The lint's remaining hits are ordinary English identifiers and data values that
its word match catches (`Enter`, `layout-dashboard`, `loading="lazy"`). Anything
new that shows up there and is user-visible French is a missed string.

## Screenshots

`python scripts/screenshots.py` regenerates `docs/screenshots/` in English. Pass
`--lang fr` for the French set.
